# 地图路线重构（分叉/合并，去除蜘蛛网）设计

> 功能：把地图从「密集蜘蛛网」改成杀戮尖塔式——几条清晰路径、少量分叉与合并。

## 1. 目标与范围

- 每层节点数保持不变（2~4，居中蛇形）。
- 只改边的生成方式，让地图呈现「有分叉、有合并」的清晰路线，而非高密度的交叉连接。
- 保持既有保证：每个节点（BOSS 层除外）至少 1 条出边、每个节点（首层除外）至少 1 条入边 → 每条路都能走到 BOSS，无死路。

## 2. 现状与问题

- 现有算法：5 条随机游走路径 + 强制「补边」（每节点保底 1 出/1 入）。
- 实测（200 样本地图）：平均每层 4.6 条边；节点出度分布 1→58%、2→35%、3→8%。
- 问题：35% 节点 2 出边、8% 节点 3 出边，加上交叉补边，视觉呈蜘蛛网。

## 3. 新算法

替换 `gen.js` `_generate` 的第 3 步（游走）与第 4 步（补边），合并为一步「局部出边 + 入边合并」：

1. 自顶向下逐层 `l → l+1`：
   - 每个本层节点，在斜率 `maxSlope` 范围内的下层节点里连 **1 条**出边；
   - 若候选 ≥2 且 `rnd() < branchProb`，则连 **2 条**（分叉，去重）；
   - 每层处理完后，若某下层节点 **0 入边**，从本层补 1 条（合并）；补边时**优先选出度 <2 的本层节点**，避免某节点出度突破 2。
2. 删除原「连通性校验」步（每节点 ≥1 出边已保证必达 BOSS，冗余）。

结果：出度 1 或 2，绝大多数 1；入度 ≥1；无 3 出边节点。

## 4. 参数（`balance.js`）

- 新增 `map.branchProb: 0.25`（分叉概率）。
- 删除 `map.walkCount`（已无用）。

## 5. 测试

- `test_gen.mjs`、`test_branches.mjs` 现有断言继续通过（每节点 ≥1 出边、全图可达 BOSS、斜率约束）。
- 新增稀疏性断言：任意节点出度 ≤2（并统计平均出度下降）。

## 6. 涉及文件

- `resources/app/src/pts/map/gen.js`（边生成重写）
- `resources/app/src/pts/balance.js`（加 `branchProb`、删 `walkCount`）
- `tests/test_gen.mjs`（加稀疏性断言）
