## 一、项目概述

### 1.1 项目定位

一句话定位：**结合"三国杀式回合制卡牌战斗"与"杀戮尖塔式爬塔构筑"的独立单机肉鸽（Roguelike）游戏**。

- 形态：**独立游戏**——战斗层复用无名杀开源引擎代码，爬塔层自研；**不是无名杀的扩展**，不嵌入无名杀运行，打包为独立可执行游戏。
- 类型：单机、PvE、回合制卡牌、肉鸽爬塔、持久强化构筑（局内无个人卡组）。
- 平台：PC 优先（无名杀本身跨平台：网页 + Electron 桌面端）。
- 与参考作品的根本区别：
  - 不是动作游戏——全程无实时操作，与三国杀一样"摸牌、出牌、判定、弃牌"；
  - 不是多人身份局——没有主公/忠臣/反贼，胜负标准是"击败当前房间的敌人并向上爬塔"；
  - 借鉴边界：**战斗层 = 100% 三国杀标准**（标准规则 + 标准 160 张牌堆），**只有爬塔外层（三层地图/节点/奖励循环）借鉴杀戮尖塔**；无动作操作、无能量制、无个人卡组。

### 1.2 参考作品与角色界定（重要事实澄清）

| 参考对象 | 我方持有资产 | 本项目中的角色 |
| --- | --- | --- |
| 无名杀（noname） | 完整 JS 源码（位于本机打包版 `resources/app`，GPL-3.0 许可证） | **技术底座**。fork 其开源代码为工程起点，复用战斗引擎、AI、UI、扩展机制；本项目成果以 GPL-3.0 同名许可提供，独立发布 |
| 杀戮尖塔 2（本地 `D:\sts`，v0.107.1，Godot 引擎） | 游戏本体 + 社区 mod，**无公开源码** | **仅玩法设计参考**。它是闭源商业软件，本项目不引用其任何代码、美术、文案，只借鉴"分支地图、意图显示、奖励构筑、商店/篝火/事件"这类**玩法概念**（玩法概念不受版权保护） |

### 1.3 扩展性原则（继承无名杀）

默认初始武将为**零技能白板**，游戏强度完全来自爬塔过程中获得的构筑物。同时，玩家可以像无名杀一样**自制并导入扩展**（武将、卡牌、敌人、事件等），第三方内容统一注入本项目的内容池。

## 二、目标与核心体验

五条核心体验目标（继承初稿，作为所有设计决策的检验标准）：

1. **像三国杀一样出牌**：保留杀、闪、桃、酒、锦囊、装备、距离、攻击范围、判定、濒死救援等完整核心机制。
2. **像杀戮尖塔一样爬塔**：三层随机地图、分支路线、节点房间、战斗奖励、事件选择、商店、休息。
3. **每局都不一样**：随机地图、随机敌人、随机奖励、随机事件。
4. **策略重于操作**：依赖手牌管理、出牌顺序、目标选择、资源取舍，无反应速度要求。
5. **易上手，难精通**：新手用白板武将+杀闪桃即可打出基本战斗；高手用技能连锁、装备配合、附魔组合打出成型流派。

## 三、玩法总览

### 3.1 一局完整流程

```
开始新的一局
   ↓ 选择武将（默认：白板"无名小卒"，体力4，无技能）
进入第一层塔（塔底 → 塔顶）
   ↓ 在分支地图上选一条路走一步
   ↓ 到达节点 → 按节点类型结算：
        战斗/精英战 → 出牌对战 → 胜利 → 奖励三选一 + 金币
        事件 → 剧情选择
        商店 → 买强化/附魔服务/道具
        休息 → 回血/强化升级/换金币
        宝藏 → 高价值奖励（可能带代价）
   ↓ 抵达层顶 → 首领战 → 胜利 → 进入下一层
（共三层）
   ↓ 击败第三层首领 → 通关结算
玩家体力归零且无人救援 → 失败结算（记录、解锁）→ 可立即重开
```

### 3.2 局内 / 局外资源划分

| 范围 | 资源 |
| --- | --- |
| 局内（一局爬塔） | 体力、金币、技能、特殊武器、手牌附魔词条、兵书宝物、一次性道具、当前层与进度（**无个人卡组**，每场战斗共用标准牌堆） |
| 局外（跨局保留） | 解锁内容（武将变体、起始强化、难度梯度）、统计数据（通关次数、最佳记录）、每局种子 |

局外成长只提供**新构筑选择与挑战目标**，不直接堆叠数值。

### 3.3 玩法规则冻结声明

本文第四章至第六章构成**玩法定稿基线（v2.3）**：机制层面不再变更，后续只允许【可调】数值微调与 Bug 修复；任何机制变更需回到本文档重新评审。主题/剧情/文案不在此约束内（见 6.4）。

## 四、战斗系统（核心）

### 4.1 规则继承声明

**战斗规则 = 无名杀当前标准规则全集**（杀、闪、桃、酒、锦囊、装备、距离、判定、濒死、无懈可击响应、体力=手牌上限）。不引入杀戮尖塔的能量制，也不引入杀戮尖塔的个人卡组制。

**牌堆原则**：每一场战斗使用固定的**标准 160 张牌堆**（标准版 + 军争篇，具体以无名杀标准包 `lib.card.list` 为准），玩家与所有敌人从同一牌堆摸牌——与正常三国杀完全一致。**不存在个人初始卡组与卡组构筑**：爬塔获得的永久强化（技能/特殊武器/附魔/兵书/道具）全部以"牌堆之外的持久增益"形式存在（见第五章）。

相对标准规则，仅做以下 **5 处单人 PvE 改造**：

1. 玩家 1 人 vs 1–4 个 AI 敌人（"一对一 / 一对多"）。
2. 敌方**意图可视化**（见 4.4）。
3. 敌人只带**简化技能**（普通敌 0–1 个技能，精英/首领 1–3 个，详见第七章内容量）。
4. 一场战斗结束后牌局清空**重置**、牌堆重新洗混；玩家的**持久状态**（体力、技能、特殊武器、附魔词条、兵书、道具）**带出战场**进入下一房间。战斗中从牌堆摸到的普通装备牌只在当场生效，战斗结束随牌局洗回。
5. 移除身份系统；胜负标准 = 场上敌人全灭（胜利）或玩家死亡且无救援（失败）。

### 4.2 一个完整回合

玩家回合（与三国杀一致）：

1. **准备阶段**：处理回合开始效果。
2. **判定阶段**：逐张结算延时锦囊（如乐不思蜀、兵粮寸断）。
3. **摸牌阶段**：默认摸 2 张（技能/兵书可增减）。
4. **出牌阶段**：使用基本牌、锦囊、装备，发动技能，对目标出杀等。
5. **弃牌阶段**：手牌数超过手牌上限（=当前体力）时弃牌。
6. **结束阶段**：触发结束效果。

随后进入**敌人行动阶段**：各敌人按座位顺序依次执行 AI 决策的一回合（攻击/响应/使用牌/发动技能），结算动画从简加速。

### 4.3 一对多与距离系统

- 座位编排：玩家固定座位 0，敌人顺时针占座位 1..N。
- 距离规则沿用无名杀：两角色距离 = min(顺向座位差, 反向座位差)。
- 攻击范围基础 1，武器与 ±1 坐骑照常修改范围/距离。
- 战斗形态定位：
  - **1v1**：单个强敌，考验预判、防御资源管理、爆发时机；
  - **1v2~1v4**：多敌小队，考验集火选择、控制威胁单位、先解除控制效果。

### 4.4 敌人意图系统（借鉴杀戮尖塔）

- 每个敌人在自己的回合结束时，公开声明**下一回合意图**，显示在其武将牌旁（图标+数值）。
- 意图类型 v1 共 6 类：

| 意图 | 含义 |
| --- | --- |
| 攻击 | 声明将使用的杀/攻击手段及预估伤害 |
| 防御 | 声明将进入防御姿态（留闪/装甲） |
| 控制 | 声明将使用的延时控制（乐不思蜀/兵粮寸断类） |
| 强化 | 给自己或队友上增益 |
| 锦囊 | 声明将使用的即时锦囊（如顺手牵羊） |
| 待机 | 不做显著动作 |

- 意图的意义：把"随机挫败感"转化为"可规划的防御决策"，与"策略重于操作"目标直接对齐。
- **显示时机**：敌人在自己回合结束时生成下一回合意图并持续显示；被延时锦囊控制（如乐不思蜀）时意图自动变为「跳过」。
- **AI 决策规则（v1 决策树，按优先级）**：
  1. 濒死可自救 → 使用桃/酒；
  2. 可击杀玩家 → 全力输出；
  3. 玩家威胁高（装备/兵书加成明显）→ 防御或拆牌；
  4. 否则按敌人角色权重在攻击/强化/锦囊间选择。

### 4.6 濒死与救援

沿用三国杀：体力降到 0 进入濒死，可用桃/酒（酒自救）或技能救援；无法救援则该角色退场。PvE 中无队友救援，玩家死亡 = 本局失败。

### 4.7 战斗节奏与结算规则

- 战斗之间体力**不自动回复**；回复只来自：战斗内的桃、休息节点、一次性道具。
- 首领战胜利后不回血（保持压力感）【可调】。
- 玩家死亡（濒死无人救）= 本局立即失败，**无复活机制**。
- 单机无操作时限；敌人回合以加速节奏呈现（约正常速度 1/2）【可调】。
- 中途退出：`runState` 已持久化，随时恢复续玩。

## 五、构筑与成长系统

### 5.1 胜利奖励：三选一

战斗胜利后从随机 reward 池中三选一，池子按稀有度加权（普通/稀有/史诗 = 60/30/10 【可调】）。

### 5.2 五类构筑物

1. **新技能**：从**中性技能池**（非武将专属）三选一，常驻生效。**数量无上限，可无限叠加**——技能数量正是流派构筑的强度来源与主成长轴之一。技能格式 = 无名杀 `lib.skill` 标准事件驱动写法。
2. **特殊武器**：持久强化，**不属于牌堆**：每场战斗开始前自动体现在玩家的武器槽（攻击范围/特效）。它与战斗内从牌堆摸到的装备牌是**两条独立通道**——牌堆装备牌按标准规则使用（仅在当场生效，战斗结束洗回牌堆），特殊武器的效果跨战斗持续。武器自带特效词条（例：对距离 2 以内目标可额外指定一个目标）。
3. **手牌附魔（按牌型）**：选定一个牌型（如【杀】、【闪】或所有普通锦囊），为其附加**持久词条**——此后每一场战斗，你该牌型的所有手牌都带此特效。附魔词条池 v1 共 6 条：

| 词条 | 效果 |
| --- | --- |
| 破甲 | 该杀结算时无视目标防具 |
| 背刺 | 该杀造成伤害后弃置目标 1 张牌 |
| 销骨 | 该杀造成伤害后目标再失去 1 点体力 |
| 穿杨 | 该杀攻击范围 +1 |
| 连珠 | 该杀使用后，本回合可再使用 1 张杀 |
| 凝神 | 该杀是最后一张手牌时，伤害 +1 |

4. **全局增益（兵书/宝物）**：类似遗物的全局被动，包装为三国语境（例：摸牌阶段多摸 1 张、手牌上限 +1）。v1 池 5 条。
5. **一次性道具**：类似杀戮尖塔的药水——恢复类（回体力、濒死时强救）、进攻类（立即造成伤害、弃置目标装备）、功能类（辅助判定/转移目标等），每件仅限当场战斗使用一次，用后消失；来源为商店/事件/宝藏，具体条目在实现阶段以平衡表定标。

各通道存栏上限见 4.5 表（技能**无上限**；附魔 4 / 兵书 3 / 道具 3）；附魔/兵书/道具超限时获得的强化可选择替换或放弃旧项。

### 5.3 各节点的获取途径

| 来源 | 可获得 |
| --- | --- |
| 战斗胜利 | 构筑三选一（技能/特殊武器/附魔/兵书/道具）+ 金币 |
| 精英战胜利 | 构筑三选一 + 更多金币 + 至少 1 个高稀有度项 |
| 首领战胜利 | 兵书（全局增益）+ 高稀有度构筑 |
| 商店 | 购买技能/特殊武器/一次性道具、附魔服务 |
| 休息 | 回满体力 / 升级 1 项构筑（技能强化或附魔词条升级） / 换金币（三选一） |
| 宝藏 | 高稀有度构筑（武器/兵书/技能），15%【可调】概率伴随代价 |
| 事件 | 有风险的选择（收益、代价、抽奖） |

### 5.4 局外成长

- 解锁新武将变体（带不同起始构筑倾向）、新起始强化（如开局自带 1 条附魔词条并占用容量）、新难度（进阶模式）。
- 记录最佳通关路径、种子、统计。
- 原则：局外不解锁"数值膨胀"，只解锁"选择与挑战"。

## 六、地图与节点设计

### 6.1 三层结构

| 层 | 主题 | 特点 |
| --- | --- | --- |
| 第一层 | 入门战场 | 敌人较弱，教学式接触杀闪桃酒、距离、装备、锦囊 |
| 第二层 | 险地试炼 | 精英增多，敌人开始带控制、爆发、多段攻击 |
| 第三层 | 塔顶决战 | 首领带阶段机制：血线阈值变技能、召唤随从、强化判定、限制出牌 |

### 6.2 节点类型（7 类）与效果

| 节点 | 效果 |
| --- | --- |
| 普通战斗 | 1v1 或 1v2 普通敌人（0–1 个技能）；胜利 → 构筑三选一 + 金币 |
| 精英战斗 | 精英敌（1–3 个技能组合）；胜利 → 构筑三选一 + 更多金币 + 至少 1 个高稀有度项 |
| 事件 | 展示 2~3 个选择，风险与收益并存，选择后立即结算 |
| 商店 | 展示 4~6 件商品（技能/特殊武器/一次性道具）与附魔服务、补给服务，用金币购买 |
| 休息 | 三选一：回满体力 / 升级 1 项构筑 / 换金币 |
| 宝藏 | 开箱获得 1 个高稀有度构筑（武器/兵书/技能），15%【可调】概率触发代价 |
| 首领 | 每层 1 个固定首领（阶段机制：血线变技能/召唤/强化判定/限制出牌）；胜利 → 进入下一层或通关 |

获取途径与 5.3 表一致。

### 6.3 地图生成规则

- 每层 = 12~15 个普通节点 + 层顶 1 个首领节点。【可调】
- 拓扑：2~3 条并行分支路径构成网状 DAG（有向无环图，仿杀戮尖塔），玩家每次沿边前进一格。
- 硬性约束：
  - 首领固定在每层末尾，是当前层所有路径的必经汇合点；
  - 休息节点不能连续出现（跨节点间隔 ≥2）；
  - 精英节点前必须存在可到达的商店或事件节点；
  - 每层至少 2 个事件节点；
  - 宝藏节点每层最多 1 个（约 15% 概率出现）。
- 同层同一纵向深度可为多类型节点，形成"绕路取舍"（要奖励还是要稳）。
- **生成算法（v1）**：每层纵向 10~12 步（列）；第 1 列为 3 个起始节点（以战斗/事件为主）；中间每列 2~4 个节点；每个节点向下一列连 1~2 条边、边不交叉；倒数第二列所有节点汇连首领。节点类型先按 4.5 分布权重随机放置，再用上述硬性约束修正（不满足则重投该节点类型）。

### 6.4 爬塔主题包装与 PvE 参考来源（方向性设计，本版不锁定）

**本节只固"玩法框架"，具体剧情与文案不在本版需求内**，标记三条原则：

1. **三国历史分幕主题（示例，后续定稿）**：三层可对应三个历史阶段，实现时套用即可、机制不变：

| 层 | 主题示例 | 包装方向 |
| --- | --- | --- |
| 第一层 | 黄巾之乱 | 普通敌人 = 黄巾军杂兵；首领 = 某路渠帅；教学分幕 |
| 第二层 | 群雄割据 | 精英/敌人 = 各路诸侯部曲；事件偏征伐与选择 |
| 第三层 | 中原逐鹿 | 首领 = 枭雄级人物（阶段机制）；通关 = 天下大势结算 |

   剧情演出深度、具体命名、文案语气待定，但**节点类型、生成规则、奖励循环不受主题影响**（即换一套主题数据即可成另一套皮肤，这同时为后续扩展包复用地图框架留接口）。

2. **已有 PvE 模式调研（机制借鉴池）**：实现前调研并归档，产出"敌人/AI 组织方式原型清单"带入 M1：
   - 无名杀内置：`mode/boss.js`（挑战模式，最近似的连续 PvE 结构）、`mode/tafang.js`（塔防）、`mode/single.js`（单挑模式，1v1 战斗组织先例）；
   - 三国杀官方与社区的 PvE 玩法（挑战/讨伐类）与相关自制扩展，只借鉴回合安排与难度曲线思路，不搬运美术文案。

3. **剧情与主题延后原则**：为避免范围蔓延，本项目的剧情、过场、台词一律归入 M6 之后的"后续可扩展"，主开发线只保障玩法与机制完整可用。

## 九、技术实现方案

### 9.1 载体形态：独立游戏工程（不是无名杀扩展）

```
《爬塔杀》工程（fork 自无名杀开源仓库，独立发布）
├─ battle/     复用的无名杀战斗引擎：牌堆、回合流程、技能、装备、AI、战斗 UI
├─ roguelike/  自研爬塔层：地图生成、节点调度、奖励引擎、意图系统、存档、主控循环
└─ content/    内置内容包（技能/敌人/事件/词条数据表）+ 扩展注册接口
```

工程依据：直接以无名杀开源仓库为底座 fork，剥离无关模式与素材；战斗引擎全量复用，爬塔主循环与新界面为自研模块，最终打包为独立可执行程序（Electron）与网页版。

### 9.2 模块架构

```
 ┌──────────────────────────────────────────────┐
 │                爬塔主控（模式事件流）                │
 │   楼层调度 / 节点切换 / 胜负判定 / 局外状态流通      │
 └──────┬───────────┬──────────────┬────────────┘
        │           │              │
   战斗代理      地图生成器       奖励引擎
  （子对局封装）  （DAG 生成）   （三选一/权重抽取）
        │           │              │
 ┌──────────────────────────────────────────────┐
 │   意图系统 │ 词条注入 │ 内容注册器（扩展API） │ UI组件 │
 └──────────────────────────────────────────────┘
        │
   存档（IndexedDB）
```

### 9.3 玩法概念 → 无名杀机制映射表（实现路径核心）

| 玩法概念 | 无名杀实现方式 |
| --- | --- |
| 一场战斗 | 主控循环中封装"子对局"：`game.resetGameProperties` 清盘 → 重设座位/玩家状态 → 引擎原生 phase 流跑完整回合制 |
| 标准牌堆 | 直接复用无名杀标准包 160 张洗混牌堆（无个人卡组），每场战斗重洗 |
| 持久状态带出战场 | `runState` 对象（体力/技能/特殊武器/附魔/兵书/道具）持久保存；子对局开始时回注 |
| 敌人 | 自定义武将包 `lib.characterPack.rogu_*`；敌人属性 = 体力/技能/行为权重 |
| 敌人回合行动 | 引擎原生 phase 流复用，敌人间加速结算 |
| 敌人意图 | AI 在 `chooseToUse` 决策点输出预估意图 → `ui.mark` 渲染到敌人牌旁 |
| 手牌附魔 | 按「牌型 → 词条」注册子技能，用 `skill.mod` 做规则修改（无视防具、杀次数+1 等），每场战斗开局挂载到玩家身上 |
| 兵书（全局增益） | 玩家常驻被动技能（trigger/enable 事件钩子现成） |
| 一次性道具 | `lib.card` 新 type（item）+ 使用即销毁逻辑注册 |
| 爬塔地图 UI | `ui.create.div` + SVG 画分支图，点击节点触发结算 |
| 存档 | 无名杀自带 IndexedDB 封装 `lib.db`，新增 `roguStore`（runState / unlock / stats） |
| 奖励池 | JS 数据表对象 + 权重抽取函数（稀有度加权） |
| 技能池 | `lib.skill` 标准格式，扩展内容天然兼容 |

### 9.4 关键流程伪代码（示意）

```
# 地图生成（每层）
nodes = 按约束(6.3)生成分支DAG(12~15节点)
boss 在末尾汇合；返回 {layers: [], edges: []}

# 主循环
while 玩家未死亡 且 未通关:
    node = 等待玩家选路
    result = dispatchNode(node)        # 战斗/事件/商店/休息/宝藏
    if result == 战斗胜利: grantReward(三选一, 金币)
    if 被敌全灭 or 玩家死亡: settleFailure()
    if node == 首领 且 胜利: nextFloor() or settleVictory()
```

## 十一、验收标准

1. 玩家能完整走通"进塔 → 三层 → 通关"与"失败 → 重开"两条主流程。
2. 战斗手感等同于三国杀：摸牌、出牌、判定、弃牌、装备、濒死全部按标准规则工作。
3. 相邻两局的地图、敌人、奖励存在可见随机差异。
4. 至少存在一个可通关角色（白板武将）与一个可成型流派（如附魔流/兵书流）。
5. 敌人意图可在回合中观察并据此防御（实测可规划出防掉攻击的操作）。
6. 胜利奖励三选一、失败重开入口均可用。
7. 玩家可自制一个扩展（至少含 1 个新敌人或 1 张新卡）并成功进入对应内容池。
8. 十一阶段交付：设计文档 + 代码说明 + 测试记录完整。
9. `pnpm lint` 通过且无引擎文件修改登记表之外的核心改动。
10. 一次完整对局（3 层）时长控制在 40~70 分钟。【可调】
